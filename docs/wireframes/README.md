# Wireframes

The implemented UI is server-rendered Razor with focused role surfaces rather than static mockups.

## Student

- Dashboard summary with support actions.
- Privacy panel for monitoring consent and student-number verification state.
- Manual in-app prompt preference and prompt response actions.
- Mood journal, booking, forum, and crisis-resource routes.

Student screens do not show risk probability, queue state, hidden monitoring data, or model decisions.

## Counselor

- Queue view with real model availability, schema, latest run status, and authorized risk-case details.
- Appointment workspace for upcoming/recent sessions.
- Fixed-template manual prompt creation from eligible counselor/student interactions.

## Admin

- Risk Monitoring view for ML availability, artifact/schema status, snapshot import, CSV template download, manual scoring, run history, and student-number claim review.
- Operations dashboard for real system KPIs and records.

## Landing

The public landing page presents the platform truthfully: consent-gated monitoring, quality-gated model use, human review, no diagnosis, and no automatic risk outreach.
